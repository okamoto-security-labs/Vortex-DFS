Why Vortex exists

Credentials are not a reason to execute.

Most autonomous systems assume that possession of credentials is enough. Vortex inserts a deterministic decision boundary between intent and execution.

Decision semantics

Three outcomes. No ambiguous fallback.

The initial enterprise policy demonstrates a typed, auditable decision model. Thresholds are explicit and test-covered.

ALLOW
≥ 0.90

Authorization is granted and the external executor may begin.

REVIEW REQUIRED
0.60–0.89

Execution pauses until an independent approval is provided.

BLOCK
< 0.60

Authorization is denied. The executor is not started.

Runtime pipeline

Evaluation before delegation.

The authorization API returns a structured report. The runtime does not execute tools; consumers decide how to handle the result.

01
Collect contextNormalize the request and available runtime evidence.
02
Load policySelect an explicit, versionable policy profile.
03
Evaluate trustApply deterministic rules to the supplied evidence.
04
Generate reportReturn decision, reason, policy, score, and latency.
05
Delegate or stopApproved requests reach the executor; denied requests do not.

Reusable API

Integrate the decision boundary, not the demo.

Vortex exposes a runtime authorization API that can be consumed by Agent SDKs, workflows, services, and future adapters.

main.rs
use vortex_dfs::runtime::{authorize, AuthorizationRequest};

let report = authorize(AuthorizationRequest::new(
    0.94,
    "Enterprise Default",
));

if report.is_allowed() {
    agent.run(...).await?;
} else {
    // Review or block without starting the executor.
}
Engineering properties

Infrastructure behavior, not a marketing wrapper.

The current milestone focuses on explicit control flow and a reusable boundary. Dynamic evidence is the next engineering phase.

01 / DETERMINISTIC

Explicit policy behavior

Identical input and policy produce the same typed decision and reason.

02 / FAIL CLOSED

No unauthorized delegation

Blocked and review-required paths terminate before the Agent SDK starts.

03 / AUDITABLE

Structured authorization report

Decision, trust score, policy profile, reason, and latency remain visible.

04 / TESTED

Core paths covered

Unit tests verify allow, review, and block behavior across policy thresholds.

05 / MODULAR

Executor-independent runtime

The authorization engine is a reusable library rather than Agent SDK logic.

06 / GOVERNED

Protected delivery pipeline

Pull requests, required CI checks, and protected main-branch rules guard changes.
