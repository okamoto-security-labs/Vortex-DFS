Approved tool ≠ authorized action.

Vortex DFS explores deterministic policy checks at the execution boundary of AI agent workflows. An MCP tool inventory answers which tools exist; a runtime gate asks whether this particular request meets its policy.

Where the guard fits

Agent request → Evidence + policy → Vortex decision → Protected executor

A rejected request must never invoke the guarded executor. This is a code-level invariant, not a claim of complete MCP integration.

What a customer pilot would validate

One agreed MCP workflow, explicit authorization criteria, legitimate and unauthorized tool calls, bypass attempts, reason codes, and observed false positives. Success requires actual adapter integration and measured results—not screenshots of a simulated decision.

Important limitations

Vortex DFS is experimental pre-alpha. The repository does not claim a production MCP Tool Runner integration, production identity enforcement in the HTTP path, immutable audit retention, or independently established production efficacy. No current CI pass or performance measurement is asserted by this page.
